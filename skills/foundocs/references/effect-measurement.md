# Optional effect measurement: automatic host procedure

This is a host-agent procedure, not a request for the user to type commands. Run it automatically on a supported shell-capable host when the project's policy is ON. Never enable the project's policy yourself. Normal Foundocs work continues if a sample is unavailable, with the reason reported. Do not silently fall back to another model/runner.

At the start of each information-acquisition task, before its first index, TL;DR, search or content exposure, call `get_effect_measurement_policy` once with the explicit configured project_id. Reuse this response throughout that task. OFF means no `measure prepare`, no `measure run`, no evaluation child and no probe inference. The policy response still consumes ordinary main-task context.

For ON, use a fresh lowercase UUID taskId once per information question. Before any Foundocs exposure, form a short brief from the user's current question and context already known: question (1–2,000 characters), knownContext (0–4,000), criteria (1–10 unique `{id,description}`). Do not include expected answers, full conversation, Foundocs answers, later conclusions or reconstructed history. If this task already saw Foundocs content before preparation, skip measurement; do not relabel it with a new taskId.

Automatically execute the installed CLI with stdin JSON (never include credentials):

```
foundocs-setup measure prepare --root /absolute/governing/project
```

Input is `{policy, host, brief:{taskId,question,knownContext,criteria}, allowlist:["src","README.md"], excludePaths:["path/to/known-foundocs-export"]}`. Pass the exact policy response's data object. `host` is the session object emitted by the installed SessionStart hook: `{client:"claude_code", sessionId, transcriptPath}`. Use only the current host-provided session identity/path; never search other sessions, infer a model, or ask the user to enter a model ID. If this metadata is absent, report `working_model_unavailable` and continue normal reads without tracking. The installer reads only the current session's latest assistant model metadata (not conversation text into the brief/server), freezes that exact model with the pre-exposure brief, and uses it for both arms. The old `policy.model` is ignored. A returned skipped reason is not a preparation and must not trigger probes. Use the installed `foundocs-setup` executable or `npx --yes @foundocs/foundocs-setup@latest` if that is the configured launcher. Do not put interpolated user text into shell command syntax: use a quoted heredoc or a private temporary input file and remove it afterward. Choose only user-authorized local original-source paths relative to the governing root; inspect provenance locally before selecting them. Do not use `.`/absolute/parent paths. Ordinary local user docs and extensionless UTF-8 sources are allowed. Explicitly exclude any known exported Foundocs docs/knowledge and already generated answers. Mandatory exclusions include `.git`, dependencies, credentials, `.env`, Foundocs config, installation/skills/session folders, AGENTS.md/CLAUDE.md, and legacy artifacts docs/knowledge/history. Symlink/hardlink sources and binary files are excluded. File/byte limits fail the entire snapshot, never silently truncate it. Unrecognized copied knowledge remains a source-provenance limitation.

Only `status:"prepared"` authorizes measurement tracking. Save its `effectPreparationId` and the same taskId. Include BOTH on every subsequent `get_project_context` (including view:index), `search_docs`, `explore_docs`, `get_doc` and `get_docs`, retaining them across cursors/chunks. Gather all task retrievalIds, not only helpful ones. Do not retrieve extra content for the experiment or replace the captured response with a full document.

When that question's information acquisition is finished, report each retrieval's usual beneficial/not_beneficial evaluation. If at least one is beneficial, automatically invoke ONCE:

```
foundocs-setup measure run --root /absolute/governing/project
```

stdin: `{taskId,retrievalIds:["all-task-retrieval-uuids"]}`. Multiple useful reads belong to this one run. The server chooses sampling/admission and arm order; the coordinator uses the exact captured text only for the with arm. Never call the model manually to reproduce a failed or uncertain run. A duplicate, crash or lost response must not create another probe or taskId. If the coordinator was interrupted or crashed, automatically invoke `measure flush` with the SAME taskId on resumption: it recovers only normalized observed costs after the old owner has exited and never spawns a probe. Do not call prepare with another taskId to reproduce it. For `report_pending`, use `measure flush --root ...` with `{taskId}` to resend only the identical report. A definite rejection requires investigation; it is not an uncertain transport retry, and changed payloads need a new requestId.

Supported: a local authenticated Claude Code 2.1.312 working session with safe-mode/restricted on macOS. The installed SessionStart hook supplies the session identity; the current transcript must contain fresh model metadata for this same project/session. Restart a session after installing/updating hooks if its identity is unavailable. A user-facing model override is never accepted. Codex working sessions are currently `unsupported_runner`: do not evaluate their work using Claude. Missing/stale/unknown model metadata is `working_model_unavailable`; aliases, shell-less MCP/Chat/Desktop hosts, missing CLI/login/required isolation, Linux or Windows pending platform canary verification, external network sources and fallback models are unsupported. No preparation/model-discovery inference is used. Each arm is a fresh process in an independent sibling snapshot, Read/Glob/Grep only, empty MCP and settings sources, no persisted sessions, no shell/write/network/delegation. Foundocs credentials stay in the coordinator. The provider's existing local auth is needed; an execution sandbox that hides Keychain may make the runner unavailable.

Each arm starts at most once. The coordinator checks server permission before spawn and every 5 seconds; network failure, OFF, changed revision or lease expiry stops the child and prevents the next arm. Termination is SIGINT, 3 seconds later SIGTERM, then 2 seconds later SIGKILL. An already in-flight provider request can still incur cost. Max turns is not an API request count; token reservations and estimated USD thresholds are admission/observation limits, not hard billing caps.

The comparison is a signed sampled information-acquisition token difference, not whole-task savings. Only actual usage is reported, including failed/cancelled costs; missing fields stay null. Without enough original information, the baseline records a question and the difference is null. Evidence verification checks literal source/quote presence; satisfied criteria are agent self-assessment, not objective semantic equivalence. No judge model is used.

Raw snapshots, brief, prepareInput and captured context expire 24 hours after preparation. Normalized probes, report outbox and run/lease/hash metadata have a separate 24-hour settlement lifetime after observed completion. An unobserved crash uses the last recorded reservation/usage time + two (per-probe timeout +5s signal-grace) windows +24 hours; recovery and retry never extend it. The next measure command or MCP startup deletes expired local data; a live coordinator also aborts and purges only raw data on expiry. Journal writes serialize with cleanup and cannot restore expired raw fields. Reports can flush without raw data. A non-model watchdog kills the CLI process group on coordinator disconnect, including SIGKILL, and enforces its own timeout. An offline machine cannot guarantee an exact physical deletion time. Raw CLI transcripts are never saved by default. No automatic cleanup changes the original project.
